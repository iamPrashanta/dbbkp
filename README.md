# dbbkp-agent 🛡️

A powerful, zero-dependency, pure Bash Interactive CLI for effortless **MySQL** and **PostgreSQL** automated backups, restores, and cloud syncing.

Built natively for Linux/Unix servers, `dbbkp-agent` replaces complex manual commands and undocumented cron jobs with a beautiful, guided menu or a fully automated Headless mode. 

---

## ✨ Features

- **Logging Built-In**: All commands and debug outputs generated by the script (`[+]`, `[ERROR]`) automatically clean off their console color formatting and append locally to the file assigned in your `.env` (`ENV_LOG_FILE=./dbbkp-run.log`).
- **Resilient Retry Wrapper**: Utilizes an exponential backoff shell wrapper named `with_retry()` which attempts any network connection or massive database dump up to 3 times. If an action fails, it waits exactly 5 seconds, alerts you via terminal/log, and safely retries.
- **Piping & Progress Tracker**: Removed messy verbose outputs and fully bound MySQL and PostgreSQL successfully through `pv`, generating beautiful live tracking speed pipelines across everything.
- **SHA256 Checksums**: Backups generated out of MySQL and PostgreSQL natively compile `.sha256` sidecar checksum files alongside them. Furthermore, the built-in Cloud Transfer Module is **Checksum-aware**; if it spots a `.sha256` file next to your target backup when uploading to AWS/GDrive, it silently queues and sends it simultaneously.
- **Dual Mode Operations**: Works as an interactive prompt-driven GUI for humans, and a silent webhook-triggering daemon for `cron`.
- **Zero Dependencies**: Native Bash. No Node.js, Python, or Ruby libraries required.
- **Smart PostgreSQL Restores**: Includes built-in auto-pausing for manual app migrations (e.g. `npm run db:migrate`) and automatically runs complex `setval()` PL/pgSQL loops to fix broken serial sequences after a data restore.
- **Cloud Integrations Built-in**: Send backups natively via `AWS S3`, `rclone (Google Drive/Dropbox)`, standard `rsync`, or `scp`.
- **Alerting**: Slack and Discord Webhook integration natively supported for success notifications.
- **`.env` Auto-discovery**: Prepopulate your database credentials cleanly without retyping them, saving time during high-stress incident responses.

## 📦 Installation

To download the latest script globally onto your server:

```bash
# 1. Download straight to your bin directory
sudo curl -L https://github.com/iamPrashanta/dbbkp/main/dbbkp.sh -o /usr/local/bin/dbbkp

# 2. Make it executable
sudo chmod +x /usr/local/bin/dbbkp

# 3. Launch the manager!
dbbkp
```

## 🚀 Usage 

### 1. Interactive Application Mode
Simply run `dbbkp` in your terminal to open the Interactive Module Selector. The application will securely ask for your database passwords using silent inputs.

```bash
$ dbbkp
==================================================
      DB Backup & Restore Manager                 
==================================================
1) MySQL Backup
2) MySQL Restore
...
```

### 2. Headless Automation (Cron Mode)

If you wish to completely bypass the menus and automate the process, trigger the script using `--headless`.

The script accepts the following arguments:
- `--headless` (Activates silent mode)
- `--mode=` (Options: `mysql-backup`, `mysql-restore`, `pgsql-backup`, `pgsql-full-restore`, `pgsql-data-restore`, `upload`, `download`)
- `--file=` / `--schema=` (Explicit paths to your database archives or files)
- `--method=` / `--dest=` (For Cloud syncing routing and targets)
- `--port=` (Optional: specify an SSH port for `scp` or `rsync` usage)

#### Example: Daily Automated Backup via Cron
```bash
# Add this to crontab -e
# Runs silently every night at 2:00 AM, auto-fetching credentials from your .env
0 2 * * * cd /path/to/script/dir && ./dbbkp.sh --headless --mode=pgsql-backup
```

#### Example: Automated Cloud Storage Sync
```bash
# Push directly to S3 without human input
./dbbkp.sh --headless --mode=transfer --method="AWS S3" --file=backup.sql.gz --dest=s3://my-secret-bucket/
```

## ⚙️ Configuration (`.env`)

You do not need to configure anything to run the script. However, placing a `.env` file in the same directory as where you run the script enables powerful shortcuts.

Create a `.env` file containing:
```env
# Database Credentials
ENV_DB_HOST=localhost
ENV_DB_USER=root
ENV_DB_PASS=myStrong1234567
ENV_DB_NAME=mydb

# Cloud Storage
ENV_AWS_BUCKET=s3://my-backup-bucket/
ENV_AWS_ACCESS_KEY_ID=YOUR_AWS_KEY
ENV_AWS_SECRET_ACCESS_KEY=YOUR_AWS_SECRET

ENV_RCLONE_REMOTE=gdrive:/database-backups/

# Webhooks (Slack/Discord)
ENV_WEBHOOK_URL=https://hooks.slack.com/services/T00000...
```

When Interactive mode is running, if it detects this file, it will ask:
`Do you want to proceed with these details? (y/n)` allowing you to skip tedious typing!

## 🔧 Prerequisites / Required Packages

The script attempts to degrade gracefully if certain optional tools (like `pv`) are missing. However, your server must have the foundational database clients installed for the backups to work. 

If execution fails because a tool is missing, you can quickly install the required dependencies on **Ubuntu/Debian** systems:

```bash
# Update package list
sudo apt update

# 1. Install MySQL Server + Client tools
# Includes: mysql, mysqldump
sudo apt install mysql-server mysql-client -y

# 2. Install PostgreSQL Server + Client tools
# Includes: psql, pg_dump, pg_restore, createdb
sudo apt install postgresql postgresql-contrib postgresql-client -y

# 3. Install Cloud Transfer Tools
# Includes: AWS CLI, rclone
sudo apt install awscli rclone -y

# 4. Install File Transfer / Utility Tools
# Includes: rsync, ssh/scp client, curl, zip/unzip
sudo apt install rsync openssh-client curl zip unzip -y

# 5. Install Pipe Viewer (pv) for progress bars
sudo apt install pv -y
```

> **Note:** If you only need backup/restore against a remote database server, installing just the client packages is sufficient. Install MySQL/PostgreSQL server packages only when testing or hosting databases locally.
> **Note:** For CentOS/RHEL/Fedora, you can simply substitute `apt install` with `yum install` or `dnf install`.
